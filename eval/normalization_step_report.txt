NORMALIZATION IMPROVEMENTS IMPLEMENTED
1. Title detection: positional first-block check (short, no terminal punctuation),
   language-agnostic so Persian-only titles work too; also upgrades a first line that
   was initially misclassified as a lower-level heading (e.g. a title containing a
   capitalized Latin product name).
2. Numbered Persian/English sections ("1. مقدمه", "Chapter 1", "فصل ۱", "بخش ۲") with
   run-vs-isolated lookahead: isolated numbered line -> ## heading; 2+ consecutive
   numbered lines -> a real numbered list with ORIGINAL numbers preserved (previously
   every numbered item was collapsed to literal "1.").
3. Generic short-line subsection heuristic demoted to level 3 and FIXED: previously
   counted arrows/slashes/digits as "capitalization evidence," causing false positives
   on flow-diagram lines. Now only counts genuine capitalized Latin words.
4. Trailing-punctuation check now allows "?"/"؟" at heading ends (question-style
   section titles are common in Persian/English academic writing); period/colon/
   semicolon/comma still disqualify.
5. structure_confidence calibrated by signal strength: "high" = native Word heading
   style OR strong regex signal (chapter-word/numbered-section); "medium" = weak
   generic-heuristic signal only; "low" = no headings detected at all.
6. Implicit bullet-list detection via inline lookahead: a run of 3+ short (<=55 char)
   unmarked lines becomes a bullet list even when embedded between long sentences
   (not just when an entire paragraph happens to be uniformly short). Deliberately
   DISABLED for PDF page text, where pypdf line breaks are usually just visual
   word-wrap, not real line breaks.
7. CRITICAL FIX -- DOCX: normalize_docx previously only trusted real Word Heading/
   List styles and passed every "Normal"-styled paragraph through completely
   unclassified. This was the literal cause of your reported "DOCX converted cleanly
   in text but Markdown structure still needs improvement" -- the test docx had zero
   real Word heading styles, so heading_count was 0 across the board. Now routed
   through the same shared tokenizer as TXT/PDF.
8. CRITICAL FIX -- DOCX soft line breaks: python-docx renders Shift+Enter breaks
   inside one Word paragraph as embedded "\n" in paragraph.text. These were being
   treated as one opaque multi-line blob with zero per-line classification. Now
   split into separate classifiable lines first.
9. Unified all three formats onto one shared tokenizer core (_tokenize), replacing
   three separately-drifting heuristic implementations (this is what caught and fixed
   bug #7 and #8 -- the docx path was reimplementing the same logic worse).

RISKS / ASSUMPTIONS
- Numbered-marker heading detection can misfire on rare "YEAR. sentence" patterns
  (e.g. "2025. این سال...") -- known, accepted heuristic limitation.
- Pure-Persian unmarked subsections still cannot be detected (Persian has no letter
  case, so the generic level-3 heuristic structurally cannot fire on them) -- only
  numbered/chapter-word Persian patterns are caught. Documented limitation, not a bug.
- A few short Latin acronym-like phrases ("QR check-in", "GPS check-in") inside an
  otherwise-unmarked list get promoted to ### instead of staying list items --
  cosmetic only, chunker still packs them correctly with the surrounding section.
- determaind.txt re-normalization produced heading_count=236 with expected noise:
  book front-matter lines, a literal table-of-contents listing whose chapter titles
  get caught alongside the same chapters' real headings later in the body, and some
  proper-noun false positives across 800KB of dense prose. Fine for prep purposes;
  should be spot-checked before relying on it for the real future migration.
- PDF structure detection is still purely regex/heuristic (no font-size/layout signal
  used yet; pypdf's visitor_text API could add one later without a new dependency).
- OCR fallback is readiness scaffolding only -- no backend installed, so scanned/
  image-only PDFs are flagged, not recovered, until you approve installing one.
- Chroma was not touched in any way this round; the 3 indexed documents still serve
  from their OLD flat chunks. converted/*.md + metadata are local-only prep artifacts.
